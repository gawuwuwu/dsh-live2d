# 0.13.4 · 按审查报告修复

对照 `审查报告`（m12799）逐项落实。原则：一个回复只弹一次、一轮唤醒只有一个终态、权限按「来源」判。

## 1. 统一回复生命周期（P0-3 / P0-4）

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| `pushIdleReplies` | 只比 `lastMessageId` / `lastIdentity` | 先 `claimReply(inst, key)` 抢到才发 |
| `maybeFinishChat` | 直接发 `reply` | 先 claim，没抢到只收尾 |
| `pushWakeBubble` | 直接发气泡 | 内部 claim，`deduped` 直接让出 |
| `toolBubble` | 发完不记账 → idle 再弹一次 | claim + 写回 `lastMessageId/lastIdentity/lastAt/bubbleCount` |
| `handleBubble`（HTTP） | 比 `identity` 字符串 | 同一套 claim |

- `replyKeyOf(message, text)`：`id:<messageId>` 优先，其次 `seq:<n>`，最后 `text:<sha1>`。
- `claimReply`：`text:` 键 **5 秒** TTL（同文不同轮不会永久被吞），其它键 10 分钟。
- 窗口对话（`window-chat`）由 `maybeFinishChat` 与 idle 推送共用同一把锁 —— 谁先到谁显示，另一个自动让出。

## 2. 唤醒结束路径（P0-1）

- `wakeUp` 主体改成 `try { … } finally { state='idle'; busy=false; replySource=null }`——成功、超时、异常、followup 拒绝四种路径都不会再卡住。
- `wakePlan` 的「忙」只看运行态 `['capturing','injecting','waiting-reply','running']`；历史 `completed` 不再当终态锁。
- `requestWake` 的 catch 也补 `state='idle'` + `setWakeBusy(false)`。

## 3. 完成判定

- `waitForWakeReply` 要求「出现新的稳定 assistant 消息」**且** `agent.status === 'idle'`——工具调用过程中的中间回答不会再被当成最终回复。
- `assistantIdentity` 改用 `message.id` 优先（`id:<messageId>`），没有 id 才退回「索引 + 文本哈希」，避免压缩/裁剪后误判。

## 4. 忙时与调度

- agent 正在跑：只 `collectWakeContext`（截图入 pending），不注入消息、不等待，`lastResult.code = 'wake-skipped-busy'`。
- `startWakeLoop` 改实例级：逐实例判 `wake.state`，`Promise.allSettled` 并行，实例一卡住不影响实例二。
- 窗口 ⚡ 不再用 6 秒本地定时器清忙碌，`wakeBusy` 只由宿主下发，避免「看起来能点其实必被拒」。

## 5. 权限与配置

- `handleBubble` 删掉 `modeAllows(...,'bubble')` 守卫：HTTP 路由 = 用户操作；AI 走 `toolBubble` 时仍受 `canControl(...,{source:'tool'})` 约束。
- 模式菜单「默认」标记改 `mode === 'auto'`（内部 auto = 界面「手动」）。
- `windowConfigPayload` 补 `chatTimeoutMs`——窗口不再固定按 90 秒判超时。
- `screenWatchTick` 在 `wakeEnabled` 时跳过（定时唤醒接管，避免两套定时器重复读标题）。

## 6. 截图生命周期

- `collectWakeContext` 结尾：清掉 10 分钟前的截图（连文件）；只取「尚未发送过」的最多 2 张并打 `sentAt`，旧图不会每次重复喂给 AI。
- pending 目录独立于 `CAPTURE_DIR`，`pruneCaptureDir` 不会误删。

## 7. 白底（超屏坐标）

- 现象：重开插件后模型 1 窗口整片白，切换一下窗口才消失。
- 原因：`config.json` 里的 `windowX=1943` 在当前 DPI 下超出工作区（DIP 宽 2048），超出去的那截 Windows 不重绘，透明白底就露出来了。
- 修法：`main.cjs` 新增 `clampWindowIntoWorkArea(win)`，创建窗口时把整窗夹进 `workArea`；`index.js` 的 `ready` 分支发现实际几何与配置差 > 2px 就 `applyBounds` 落盘一次。

## 8. 测试

- `tests/shell.mjs`：新增 8 条回归（completed 不锁死 / waiting-reply 仍忙 / 同 messageId 第二次让出 / 另一个 messageId 可进 / 文本键 5 秒内让出 / 过 5 秒可再来 / 窗口配置带 chatTimeoutMs）。
- `tests/client.mjs` 10 项、`node --check`、package.json（无 BOM）均通过。
- `tests/renderer-smoke.mjs` 需在**完全退出 DSH** 后单独跑（在 DSH 进程内启动 Electron 会撞 `0x80000003`）。

## 9. 已知限制

- 同一实例被多个来源同时写入时，仍可能出现「谁先抢到谁显示」的顺序差异（不会重复）。
- 唤醒的上下文（截图/标题）只在注入那一刻采集，AI 后续动作看不到历史截图。
- 超界夹取只在窗口创建时做一次；用户手动拖到屏幕外不会被强制拉回（保留自由摆放）。
