# 0.12.11 · 六项门槛修复

> 对应你 2026-11-04 20:57 的审查结论（6 项必须修 + P1-4）。本轮**只做这 7 件**，没有加新功能。
> 版本 `0.12.10` → `0.12.11`；package.json / index.js / tests / README 已同步。

## 一、逐项对照

### P0-1 semi 状态机不工作 → 已修

- 真实事件载荷是 `{ agent, status }`，session 在 `payload.agent.session.id`。
- 现在按这个顺序取：`payload?.agent?.session?.id ?? payload?.sessionId ?? payload?.session?.id ?? null`，
  并在 `agent/status` 回调里把这个 id 传给 `finishChatsEverywhere` / `pushIdleReplies` / `autoThinking` / `autoIdle`，
  四处调用统一用同一个 `eventSessionId`。
- 效果：semi 实例在自己那个会话开始思考时真的会进 manual（并播 blink），idle 时回 auto。
- 验证：`tests/shell.mjs` 里新增了「真实 `{agent,status}` 形状」的用例（见第三节）。

### P0-2 定时读屏不启动 → 已修

根因是拿根配置 `state.config.screenReadEnabled` 判定，而这个字段是**实例**字段，根配置里永远 undefined。

- `startScreenWatch()` 改成逐实例循环：按 `inst.config.screenReadEnabled` 判定、
  按 `inst.config.screenWatchIntervalMs`（下限 15 秒）各起一个 `setInterval`。
- 每次结果写 `inst.screen.watch = { at, title, process, count }`，定时器都登记 `registerCleanup(clearInterval)`，卸载不会留定时器。
- `getForegroundTitle(state, execImpl, config = null)` 新增第三参数：`cfg = config ?? state.config`，
  HTTP `/live2d/screen` 与定时器都传**实例配置**，开关与缓存都按实例算。
- `GET /live2d/screen` 返回值新增 `watch`（最近一次定时结果，没跑过就是 null）。
- `instanceSummary()` 新增 `screen: inst.screen ?? null`，`/live2d/instances` 与 diag 都能看到。
- 设置页新增「定时感知」复选框 +「定时间隔 秒（15~300）」（`client.js` 的 `toDraft` / `toPayload` 同步）。

### P0-3 没有 AI 读屏工具 → 已修

- 新增第五个工具 `live2d_screen`，语义：解析当前会话的实例 → `modeAllows(inst,'screen')` 检查 →
  检查 `inst.config.screenReadEnabled` → 调 `getForegroundTitle`。
- 返回 `title / process / at / cached / watch`；`cached` 是 1 秒缓存命中，`watch` 是定时感知的最近一次结果。
- `live2d_status` 的实例摘要里也会带 `screen`。

### P1-1 显式 instanceId 可跨会话 → 已修

- `resolveToolTarget()` 现在必须拿到当前会话 id（`selfId`），拿不到直接拒绝。
- 显式传 `instanceId` 时校验归属：
  - 实例没绑定会话 → `instance-not-bound`；
  - 绑定的是别的会话 → `instance-not-yours`（附「普通工具只能操作绑定到当前会话的实例」）。
- `live2d_status` 只返回 `config.sessionId === 当前会话` 的实例；一个都没有时给 hint，提示去设置页绑定。
- HTTP 路由的 `?instanceId=` 仍是管理语义（不校验归属），因为设置页/我在排查时要用；
  **AI 工具这一层**是收紧的。

### P1-2 气泡/窗口工具假报成功 → 已修

- `live2d_bubble`：`sent.ok === false` → 返回 `ok:false, code:'bubble-failed'`，并带上 `sent.error`。
- `live2d_window`：
  - open：`opened.ok !== true` 或 `opened.sent.ok === false` → `window-open-failed`；
  - close / reload：`sent.ok` 为 false → `window-close-failed` / `window-reload-failed`。
- 工具返回值统一带 `sent`（底层原始结果），AI 能看到「命令发出去了但窗口没接」。

### P1-3 渲染冒烟 TIMEOUT 且无法定位 → 已修

- `tests/renderer-smoke.mjs`：
  - `finish()` 失败时打印 Electron stderr 尾部 2000 字符；
  - 监听 `child.on('error')` 与 `child.on('exit')`（提前退出直接报 `code/signal`，不再干等超时）；
  - 结束用 `taskkill /pid <pid> /t /f` 清进程树（原来是 `child.kill()`，Electron 子进程会残留）；
  - `LIVE2D_PROBE_USERDATA` 指向 `tests/.smoke-userdata`，不碰真实窗口缓存。
- 实测：`RESULT pass=7 fail=0`（长文全量 1200 字、无二次截断、溢出 588/2755、滚动条显示、long 模式、短文本不误报）。

### P1-4 zoom-overlay 仍不独立 → 已修

`fitModel()` 新增 `zoomOverlay` 分支：

- 气泡高度独立：`bubbleFixedSize ? bubbleHeightPx : clamp(H × replyHeightRatio/100, 80, H×0.7)`；
- 模型可用高度 = `H - 52`（只为输入栏让位），按 `min(W/bw, availH/bh) × 0.96 × 缩放%`，**允许被气泡盖住**；
- 不再出现「放大模型把气泡越压越小」。

## 三、行为变化（容易被当成「坏了的」）

1. **AI 在我没绑定会话时会直接失败**，报 `instance-not-bound` / `no-instance-for-session`——这是有意的，不再猜。
2. **AI 不能操作别的会话的模型**（比如我不能去动另一个 IM 会话那个），也不再在 `live2d_status` 里看到它。
3. **auto 模式**下 AI 的工具调用一律 403；设置页里的手动按钮、插件内部自动动作不受影响。
4. 定时感知默认**关**，开之前要先开「读屏·标题」。

## 四、仍未做（你已接受、本轮未动）
