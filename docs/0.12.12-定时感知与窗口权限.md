## 一、定时感知改成「统一调度器」（P1）

原来的问题：`startScreenWatch()` 只在插件加载时跑一次，设置页改了不会重建；定时器 tick 只判 `state.disposed`，不看开关，所以关掉之后仍可能继续轮询。

现在：

- 只有一个 `setInterval(..., 5000)` 的调度器（`state.screenWatchBusy` 防重入），不再「每实例一个定时器」。
- **每次 tick 现场判断 4 个条件**：
  1. `inst.config.screenWatchEnabled === true`
  2. `inst.config.screenReadEnabled === true`
  3. `modeAllows(inst, 'screen')`（auto 模式跳过——后台定时器也不能绕过 HTTP/工具层的限制）
  4. `now - watch.at >= screenWatchIntervalMs`（下限 15 秒）
- 因此：设置页**开启** → 5 秒内开始读；**改间隔** → 下一次 tick 按新值算；**关掉** → 下一次 tick 直接跳过。
- 结果仍写 `inst.screen.watch = { at, title, process, count }`，`/live2d/screen`、`instanceSummary`、`live2d_screen` 都能读到。
- 逻辑抽成导出的 `screenWatchTick(state, log, { getForegroundTitle })`，测试直接调用，不用等 5 秒。

## 二、auto 模式下 `live2d_window` 也拒绝（P2）

选择「视为模型控制能力」：

- `live2d_window` 的 `execute` 在解析出实例后先 `modeAllows(inst, 'window')`，auto 模式返回 `mode-forbidden`。
- 设置页的「打开/关闭窗口」按钮走 HTTP，不受影响（那是人工操作）。
- README 里「auto 下动作/气泡/读屏一律 403」已改成「动作/气泡/读屏/**窗口开关**」。

## 三、渲染冒烟测试的 Electron 启动失败（P1）

你那边报的是 `code=2147483651 (0x80000003)`、stderr 空。直接原因很可能是 userData 放在了 D 盘中文路径（`tests/.smoke-userdata`），Chromium 建缓存被拒——正式窗口就是因为这个才把 userData 放 `LOCALAPPDATA`。

改动：

- userData 改用 `fs.mkdtempSync(path.join(os.tmpdir(), 'live2d-smoke-'))`：系统临时目录、随机名、启动前创建。
- 结束（无论成败）`fs.rmSync(..., { recursive: true, force: true })` 删除。
- 失败时打印：`electron` 路径、`args`、`cwd`、`userData`、stderr 尾部（为空时明确写「stderr 为空」）。
- 保留 `taskkill /pid /t /f` 清进程树、`child.on('error'/'exit')` 提前退出上报。

本机实测：`RESULT pass=7 fail=0`（长文 1200 字全量、无二次截断、溢出 588/2755、滚动条显示、long 模式、短文本不误报）。
