# 0.12.13 自动模式预设交互

审查报告 P1-2 指出：`auto` 模式只有「定时上气泡」，缺少点击/摸头响应、空闲小动作——即「预设动作响应点击/摸头/回答/空闲」只做了一半。

本版补上「点击/摸头」与「空闲小动作」两条，不改三模式语义。

## 1. 点击 / 摸头

- 判定在渲染层（`electron/renderer.js`）：`pointerdown` 记起点，`pointerup` 时位移 ≤6px、耗时 ≤600ms 才算一次点击。
- 只有点在模型可视范围内才算；按 `model.getBounds()` 分两区：
  - 上 32% → `head`（摸头）
  - 其余 → `body`（戳一下）
- 点在工具栏、输入栏、气泡、调整框手柄上不算。
- 窗口只上报 `{ type: 'tap', zone }`，动作选择与冷却都在宿主（`index.js`）。

宿主 `handlePresetTap(state, inst, zone, log)`：

| 区域 | 动作池（按次数轮流） |
| --- | --- |
| head | happy → tilt → nod |
| body | nod → shake → surprised |

- 冷却 `PRESET_COOLDOWN_MS = 1200`；冷却中返回 `preset-cooldown`（不排队、不补发）。
- 关闭开关时返回 `preset-disabled`。
- 下发命令：`instanceView(state, inst).windows.send({ type: 'anim', action, timeoutMs: 2600 })`，与 AI 动作走同一条参数关键帧通道。

## 2. 空闲小动作

`startPresetLoop(state, log, registerCleanup)`：

- 每 8 秒检查一次；只对 `idlePresets === true` 且窗口已就绪的实例生效。
- 开窗后第一轮只记基线（`idleAt`），不会立刻自己动。
- 之后按 20~40 秒的随机间隔，从 `blink / tilt / nod` 里挑一个。
- 刚被点过、或刚有对话动作（6 秒内）不抢。
- 与 `startScreenWatch` 一样托管在 `ctx.effect`，卸载即清。

## 3. 配置

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `autoInteract` | `true` | 点模型/摸头有反应（用户主动点，不算 AI 控制） |
| `idlePresets` | `true` | 没人理时偶尔眨眼/歪头 |

两者都在实例级（`DEFAULT_INSTANCE` / `normalizeInstance` / `INSTANCE_KEYS` / `windowConfigPayload` / 设置页复选框）。

## 4. 与三模式的关系

- 预设交互由**用户点击**触发，不是 AI 主动控制，所以三种模式下都允许；开关独立。
- `auto` 模式下 AI 自己的动作/气泡/读屏/窗口操作仍然 403（0.12.11/0.12.12 的守卫不变）。

## 5. 验收

单测新增（`tests/shell.mjs`）：

- 摸头触发 `happy`
- 冷却期内不重复触发
- 戳身体走另一组动作
- 开关关闭时不触发
- 空闲循环首轮只记基线
- `idlePresets` 关闭时不动

手工验收（需重启 DSH + 关窗重开，渲染层改动才生效）：

1. 设置页勾选「点模型有反应」「空闲小动作」。
2. 用鼠标点头顶 → 应看到 happy/tilt/nod 轮换；点头以下 → nod/shake/surprised。
3. 连点两下 → 第二下在 1.2 秒内应无反应。
4. 静置 20~40 秒 → 偶尔眨眼/歪头。
5. 关掉「点模型有反应」→ 再点无反应；关掉「空闲小动作」→ 静置不再自行动。

## 6. 已知限制

- 动作是参数关键帧（模型没有 Motions/Expressions），幅度受参数范围限制，不是骨骼动画。
- 只识别单击，不区分左右键/双击。
- 点击判定依赖窗口的 `pointerdown`；穿透态下由 0.12.7 的 `pointer-probe` 先接管鼠标，实际点击仍由 Chromium 正常派发。
