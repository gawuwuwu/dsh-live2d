## 一、P0：AI 工具（审查报告第 1 条）

**问题**：能力只挂在 HTTP 上，两个 AI 在对话里不知道自己能控制模型。

**改动**（`index.js`）：

- `export const inject` 增加 `'tools'`。
- 新增 `createLive2dTools(state, log)`，注册四个工具：

| 工具 | 作用 | 关键约束 |
|---|---|---|
| `live2d_status` | 实例/绑定/模式/窗口/模型/气泡尺寸 | 只读 |
| `live2d_anim` | 动作指令 | 白名单 + 3 s 冷却 + 2 s 超时回落 idle |
| `live2d_bubble` | 指定文字或「本会话最新回复」 | 2000 字上限、messageId 去重 |
| `live2d_window` | open / close / reload | 单实例粒度 |

- `registerLive2dTools(ctx, state, log)`：宿主没有 `tools.register` 时**只告警不抛错**（空壳/老宿主安全）；`apply` 里 try/catch 包裹，失败只写 warning。
- 工具输出统一走 `{ok, summary}`，失败返回 `{ok:false, summary}`（不抛异常，避免打断对话轮次）。

## 二、P0：会话 → 实例的唯一解析

**问题**：旧逻辑找不到就回落默认实例，会把消息/动作发到别人的会话。

**改动**：

- 新增 `resolveToolTarget(state, { instanceId, sessionId })`：
  - 给了 `instanceId` 但不存在 → `no-such-instance`（附 `available` 列表），**不回落**；
  - 只给 `sessionId` 且没有实例绑定它 → `no-instance-for-session`，提示「去设置页绑定」，附可用实例；
  - 都成立 → `{inst, resolvedBy:'instanceId'|'session'}`。
- `resolveInstanceStrict` 同样用于 HTTP 侧需要严格定位的新路由。

## 三、P0：模式权限（工具层强制）

**问题**：`auto` 模式下 AI 仍能驱动动作/气泡。

**改动**：

- `modeAllows(inst, capability)`：**只有 `auto` 拒绝**，`manual`/`semi` 放行。
  - 这里做过一次修正：初版用 `effectiveMode`（semi 在非思考期=auto）导致用户亲口要求「点个头」也被 403，已改为只看配置里的 `mode`。
- `modeForbidden(inst, capability)` → 403 `code:'mode-forbidden'`，附「切到手动/半自动再用」提示。
- 挂载点：`handleAnim`、`handleBubble`（仅 `latest` 自动推送）、`/live2d/screen`、`/live2d/screen/capture`。
- 例外：`body.auto === true` 的内部动作（`blink`/`happy` 预设）不受限；设置页手动「测试气泡」也不受限。

## 四、P1：semi 状态机

- 新增 `effectiveMode(inst)`：`semi` 在 `modeState.phase === 'manual'` 时按 `manual` 处理。
- `autoThinking(state, log, sessionId)`：对话开始 → 进入 `manual`，播一次 `blink`；`autoIdle(state, sessionId)`：结束 → 回 `auto`。
- 两者都按 `sessionId` 过滤实例（原来是全局一刀切）。
- `agent/status` 回调补传 `payload.sessionId`。

## 五、P1：定时读屏（第一层）

- 新配置：`screenWatchEnabled`（默认 `false`）、`screenWatchIntervalMs`（默认 30000，15~300 s）。
- `startScreenWatch(state, log, registerCleanup)`：每 N 秒执行 `getForegroundTitle`，结果写 `inst.screen.watch = {at, title, process}`。
- 总开关 `screenReadEnabled` 关闭时：不启动，并写一条「定时读屏被总开关禁用」的告警。
- 只读窗口标题，**不截图**；截图仍必须手动触发。

## 六、P1：调整框拖出窗口

- 渲染层：`beginDrag` → `report({type:'drag', active:true})`；`mouseup` / `cancelAdjust` / 收到 `cancel-drag` → `active:false`。
- 主进程：`pointerTimer` 先看 `entry.dragging`，光标离开窗口 ±24 px 就下发 `{type:'cancel-drag'}`。
- 渲染层收到 `cancel-drag`：收尾拖动、上报最终 `bounds`、延迟隐藏调整框。
- 目的：鼠标拖出窗口后松开收不到 `mouseup`，不再永久卡在 `dragging`。

## 七、P1：TTS 截断提示

- 原因：`autoPushReply` 先用 `ttsText(text, 500)` 截断，`speakForReply` 再判断 `raw.length > 500` 永远为 false。
- 改动：`autoPushReply` 调 `ttsText(text, 1_000_000)`（只做清洗），截断判断留在 `speakForReply`；`truncated` / `spokenChars` / `keepReadingMs` 正常下发。

## 八、P2：置顶持久化

- `pinned` 进实例配置（默认 `true`）：`DEFAULT_INSTANCE` / `normalizeInstance` / `INSTANCE_KEYS` / `windowConfigPayload`。
- `main.cjs` 建窗与切换时都用 `entry.pinned` 决策 `alwaysOnTop`。
- `ipcMain.handle('live2d:pin')` → `report({type:'pin'})` → 宿主 `patchInstance({pinned})` + 写 `config.json`。

## 九、P2：冒烟测试隔离

- `main.cjs` 支持环境变量 `LIVE2D_PROBE_USERDATA`。
- `tests/renderer-smoke.mjs` 用 `tests/.smoke-userdata`，并捕获 stderr（失败时能看到 Chromium 的真实报错）。

| 动作 | 时长 | 参数 | 说明 |
|---|---|---|---|
| `shy` | 3200 ms | `PARAM_EXP4` 满值 0.12~0.86（约 2.4 s）、`ParamAngleX` 16、`ParamAngleY` -15、`ParamEyeSmile` 1、`ParamMouthForm` -0.4 | 之前 1.5 s 只闪一下，用户看不清 |

## 十三、已知限制 / 未做

1. `auto` 模式**点击/摸头预设动作**未做（报告 P1-2 后半）。
2. 超长 Markdown（超过 2000 字）截断会丢代码块尾部，目前只做「补全未闭合围栏」，未做「按结构裁剪」。
3. 本地 TCP 控制通道**无认证、无单连接限制、无消息大小上限**（暂缓项）。
4. TTS 音频缓存（8 条 LRU）不会随配置变更清理。
5. `renderer-smoke` 的截图断言只验证 DOM/尺寸，不做像素比对。

## 十四、回滚方法

```powershell
$old = "<备份目录>"
$new = "<插件目录>"
# 1) 先退出 DSH
# 2) 覆盖回 0.12.9
Copy-Item "$old\*" $new -Recurse -Force
# 3) 重启 DSH，确认设置页版本显示 0.12.9
```

回滚只影响插件本体；`%USERPROFILE%\.dsh\dsh-live2d\config.json` 里的实例配置（含新加的 `pinned` / `screenWatch*` / `bubbleFixedSize` / `bubbleHeightPx` 字段）在 0.12.9 里会被忽略，不会报错。
