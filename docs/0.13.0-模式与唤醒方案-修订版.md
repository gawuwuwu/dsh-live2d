## 0. 与 v1 的差异一览

| v1 做法 | v2 改为 | 原因 |
| --- | --- | --- |
| `modeAllows(inst, capability)` 只看 mode | `canControl(mode, capability, source, granted)` 四维 | 同一能力在不同触发来源下结论不同 |
| 按 mode 决定推不推气泡 | 按**回复来源**（`wake-button`/`wake-timer`/`window-chat`/`external-chat`）决定 | auto 点 ⚡ 的回复必须能显示 |
| 新增 `live2d_wake` 工具 | **不提供**（只留只读 `status`） | 避免 AI 自唤醒死循环 |
| wake loop 与 `startScreenWatch` 并存 | 统一为 **wake scheduler**，旧定时感知降级为兼容 | 避免双读标题、参数职责不清 |
| 唤醒完成 = idle 时取最后一条 assistant | 状态机 + baseline（seq/最后 assistant id） | 并发/事件延迟会拿到上一轮回复 |
| pending 截图放通用目录 | 独立 `pending/<instanceId>/`，prune 不碰 | 防止被最近 10 张规则清掉 |
| `live2d_window` 改 `op` | **保留 `action`**，扩展枚举 | 不破坏现有调用 |
| 默认 30s + 自动截图 | 默认 **30s + 只读标题**（额度 60 次/滚动小时） | 成本、隐私、长期稳定 |
| 无窗口边界 | 工作区/最小尺寸/单次位移/工具栏可见/一键复位 | 「挡屏幕」是高风险能力 |

## 1. 权限模型（四维）

```js
canControl(inst, capability, ctx = {}) -> boolean
// capability: 'action' | 'bubble' | 'screen' | 'window' | 'wake'
// ctx.source: 'wake-button' | 'wake-timer' | 'window-chat' | 'external-chat' | 'preset-tap' | 'tool'
// ctx.granted: 用户本次显式授权（按钮唤醒）
```

| capability | wake-button | wake-timer | window-chat | external-chat | tool | preset-tap |
| --- | --- | --- | --- | --- | --- | --- |
| action | auto ✗ / semi ✓ / manual ✓ | 同左 | — | — | auto ✗ / semi ✓ / manual ✓ | 全 ✓ |
| bubble | 全 ✓ | auto ✗（不存在） | 全 ✓ | auto ✗ / semi ✓ / manual ✓ | auto ✗ | — |
| screen | 全 ✓（按钮=授权） | auto ✗ / semi ✓ / manual ✓ | — | — | auto ✗ / semi ✓ / manual ✓ | — |
| window | auto ✗ / semi ✗ / manual ✓ | 同左 | — | — | 同左 | — |
| wake | ✓（按钮） | auto ✗ / semi ✓ / manual ✓ | — | — | **不提供** | — |

实现：`modeAllows()` 保留为兼容包装（内部调 `canControl`），新代码一律用 `canControl`。

## 2. 回复来源与气泡

每个实例维护 `inst.replySource`：

- 注入消息时写入：`source.kind==='live2d-wake'` + `inst.wake.inflight={source:'wake-timer'|'wake-button', baseline}`
- 用户在窗口输入框发送 → `window-chat`
- 其它（DSH 界面里对话）→ `external-chat`

推气泡判定（改造 `pushIdleReplies` + `autoPushReply` 两处，两处都要改）：

```
window-chat  → 总是推（auto 也推）
wake-button  → 总是推（auto 也推）
wake-timer   → auto 不存在；semi/manual 推
external-chat→ auto 不推；semi/manual 推
```

`autoBubble=false` 仍然作为总开关，优先级高于上表。

## 3. 唤醒状态机

```
idle
 → capturing     截图 / 读标题（2s 超时）
 → injecting     agent.followup(msg)（接住 rejection）
 → waiting-agent 等 run 开始（最长 30s）
 → waiting-reply 等「新的 assistant 消息」+ agent 回到 idle
 → completed     推气泡 / 可选 TTS；写台账
 → failed        超时 / 注入失败 / agent 错误；写原因
```

- baseline：注入前记录 `{ seq: session.seq, lastAssistantId: 最后一条 assistant 的 id }`。
- completed 判定：`agent.status === 'idle'` **且** 存在 `assistant` 消息其 id ≠ baseline（不能只取「最后一条」）。
- 超时：`wakeReplyTimeoutMs`（默认 180s）→ failed（`reply-timeout`）。
- 同一实例同一时刻只允许一个 wake（状态 ≠ idle 时，按钮返回 `busy`，定时器记 `skipped:'in-progress'`）。

## 4. 统一调度器

`startWakeScheduler(state, log, registerCleanup)`：5s tick，逐实例：

1. `mode === 'auto'` → 跳过（auto 不自主唤醒）。
2. `wakeEnabled !== true` → 跳过。
3. 状态机 ≠ idle → `skipped:'in-progress'`（是否截图见 §5）。
4. `now - lastAt < wakeIntervalMs` → 跳过（静默）。
5. 额度检查用**滚动 60 分钟窗口**（不是整点）：`wake.history` 存最近 60 分钟内每次唤醒的时间戳，`count >= wakeMaxPerHour` → 暂停；提示 `额度已满，预计 HH:mm 可再次唤醒`（按最旧一条 + 60min 计算）。额度耗尽**不能静默**：设置页与 ⚡ 反馈都要显示该文案（每条实例每分钟最多提示一次，不刷屏）。
6. 上下文权限：`wakeCaptureEnabled`（=用户预先同意定时截图）或 `screenReadEnabled`（只读标题）；**两者都关** → `skipped:'no-context-permission'`，不注入空消息。
7. 否则 `wakeUp(inst, {source:'wake-timer'})`。

旧的 `startScreenWatch`：

- 保留代码与配置项（兼容旧 config.json）；
- 当 `wakeEnabled === true` 时**自动停用**该类实例的标题轮询（避免双读），面板显示「已由定时唤醒接管」；
- 未开唤醒的实例行为不变。

## 5. 截图与授权语义

- `wakeCaptureEnabled = true` 的语义明确为：**用户预先同意「定时唤醒也可以截图」**；未确认弹窗不再拦截定时截图（否则每 30s 都只能读标题，等于功能不可用）。
- 仍需满足：`screenCaptureEnabled`（总开关）+ `screenCaptureIntervalMs`（最低安全限速，默认 30s）。
- 限速未到 → 本次只读标题，不阻塞唤醒（台账记 `captureSkipped:'rate-limited'`）。
- 两个上下文开关都关：
  - 按钮唤醒 → 允许发「无屏幕上下文」的普通唤醒（用户主动，期望有回应）；
  - 定时唤醒 → 跳过，记 `no-context-permission`（不发空消息刷会话）。

## 6. pending 截图生命周期

- 目录：`CAPTURE_DIR/pending/<instanceId>/`，文件名同 `shot-<ISO>.png`。
- 触发：定时/按钮唤醒被跳过（忙）时，截图写这里，入 `pendingShots`（上限 2，丢最旧）。
- 引用：下次成功唤醒的消息里列最多 2 条路径（标注「上次你忙没看」）。
- 清理：
  - 成功注入后**不立即删**（AI 回复时才 read_image），改为「保留到下一次唤醒成功」或「mtime 超过 10 分钟」由调度器清理；
  - `pruneCaptureDir()` 只清 `CAPTURE_DIR/*.png`，不动 `pending/`；
  - 实例删除 / 关闭唤醒 / 插件卸载 → 清该实例 pending 目录。
- 容量：pending 目录 ≤ 5 张/实例（超出按 mtime 删最旧），避免长期占用。

## 7. 窗口控制（manual 专属）

`live2d_window` 保留 `action`，扩展枚举（**AI 工具不提供 `close`**，用户仍可用窗口 × 与 HTTP 管理接口关闭）：

| action | 参数 | 说明 |
| --- | --- | --- |
| `open` / `reload` | — | 不变（`close` 仅用户侧可用） |
| `move` | `x,y` | 绝对坐标 |
| `resize` | `width,height` | 160~800 × 200~1000 |
| `scale` | `scalePct` | 50~200，按模型比例换算窗口（保持宽高比） |
| `reset` | — | 回到默认位置/尺寸 |

安全边界：

- 校验用**工作区**（`screen.getPrimaryDisplay().workArea`，多屏取窗口当前所在屏）；
- 移动后必须保证「左上角工具栏区 ≥ 40×40 在屏内且可点」（否则拒绝对这次移动并返回原因）；
- 单次位移 ≤ 屏宽/屏高的一半（防瞬移）；
- 尺寸越界 → 夹到边界并告警（与配置越界「回落默认」不同：这是运行时操作）；
- `aiMoveEnabled`（默认 **false**）+ manual 才可用；auto/semi 一律 403 `mode-forbidden`；
- 禁止「同一次调用既 move 又 close」——AI 工具本身没有 close，这条只针对宿主内部调用链。

## 13. 已确认（2026-11-05）

1. 默认值：`wakeIntervalMs = 30000`、`wakeCaptureEnabled = false`（只读标题）、`wakeMaxPerHour = 60`（**滚动 60 分钟窗口**）。30s 间隔理论上每小时 120 次，额度 60 → 会出现「跑约半小时、冷却约半小时」的周期，这是已知且接受的行为。
2. `wakeEnabled` **不随模式切换自动开启**：切 semi/manual 只改能力权限；定时唤醒必须显式开；切回 auto 立即停止后续定时唤醒，已注入的一轮允许正常结束；⚡ 按钮唤醒三模式都可用，不受 `wakeEnabled` 限制。
3. AI 工具**不提供 `close`**：只给 `move/resize/scale/reset`；用户仍可用窗口 × 按钮与 HTTP 管理接口关闭。其余边界（manual + `aiMoveEnabled`、工具栏可见、单次 ≤ 半屏、越界夹取、reset 可恢复）按 §7 执行。
4. auto 的按钮唤醒：允许截图/标题与气泡回复，但**不放开 AI 动作**（`action` 在 `wake-button` 来源下仍按 auto 拒绝）；半自动/手动的按钮与定时唤醒允许动作与表情。

### 与方案的差异（实现时调整）

1. **pending 清理时机**：方案写「成功注入后清理」，实做改为「下次唤醒成功后 / mtime 超 10 分钟」——AI 是在回复阶段读图，注入后立刻删会让图消失。
2. **screenWatch 让位**：没有物理停用定时器，而是 `wakeEnabled` 为真时 `screenWatchTick` 跳过该实例（面板显示「已由定时唤醒接管」），保留旧配置兼容。
3. **额度提示位置**：设置页与 ⚡ 按钮共用同一条 runtime warning（`pushRuntimeWarning`），避免两处措辞不一致。
4. **auto 的 ⚡**：允许读标题/截图与气泡，但 `canControl('anim', wake-button)` 在 auto 下仍为 false，AI 会收到「不要做动作」的提示行。

### 已知限制

- 30s 间隔 + 60 次/小时 → 约半小时运行、半小时冷却（§13.1 已确认）；
- 唤醒会写入绑定会话的历史（§6 风险），每次唤醒一条 user 消息；
- 定时截图是「整屏」，可能包含其他窗口；
- `live2d_wake` 只读，AI 无法自行唤醒自己；唤醒只能来自用户点 ⚡ 或定时器。
