# 0.13.10 · 动作改「次数」+ 唤醒截图默认开

## 1. 动作：从「更长」改成「连做几次」

用户 m13615：「点头幅度还是不明显，这种改动不要改时间，可以改次数，如点头/眨眼多点/眨几次」。

实现：`electron/renderer.js` 给动作定义加了 `repeat` 字段，新增 `expandAnimTracks(tracks, repeat)` 把一段关键帧按次数铺开（第 i 段映射到 `i/n ~ (i+1)/n`），段尾都归零所以衔接自然。

| 动作 | 时长 | 次数 | 幅度 |
| --- | --- | --- | --- |
| 点头 nod | 2.2s | **3 次**（每次约 0.73s） | `ParamAngleY` **-26**（原 -20） |
| 摇头 shake | 2.0s | **2 次** | `ParamAngleX` **±24**（原 ±20） |
| 眨眼 blink | 0.9s | **3 次**（每次 0.3s） | 闭合到 0.02，保持约 0.1s |
| 歪头 tilt | 2.0s | 1 次 | 不变 |

宿主兜底超时仍是 4s（`handleAnim` / `playPreset`），足够 2.2s 的动作跑完。

验证：`.tmp/nod-probe.mjs` 在动作的 0.35s / 1.15s / 1.9s 各截一帧，三帧头部角度呈「低 → 抬 → 低」，说明确实点了三次（`.tmp/nod-nod-a|b|c.png`）。

## 2. 唤醒截图默认打开

之前的问题：⚡ 手动唤醒只读了窗口标题。原因是这里有两个开关——

- `screenCaptureEnabled`（设置页「允许截图」）= 全局能力，你一直开着；
- `wakeCaptureEnabled`（设置页「唤醒时截图」）= **唤醒是否附带截图**，默认 `false`。

所以唤醒消息里写的是「只允许读窗口标题，没有截图」。

改动：

- `DEFAULT_INSTANCE.wakeCaptureEnabled` → `true`；
- `MODE_SWITCH_KEYS` 加入 `wakeCaptureEnabled`，并**在 `apply` 里执行一次性迁移** `migrateModeSwitches(state)`（标记 `0.13.9-mode-switches` 写进 `config.json` 的 `migrated` 数组）——存量配置里四个开关（读屏标题 / 允许截图 / 唤醒截图 / AI 移动窗口）会被打开一次并落盘，之后你在设置里关掉就保持关闭。
- 测试环境（`ctx.__live2dConfigFile` 隔离）跳过迁移，避免断言被默认值污染。

## 3. 截图链路现在长这样

⚡ / 定时唤醒 → `collectWakeContext`：

1. `wakeCaptureEnabled && screenCaptureEnabled` → `requestScreenCapture`（PowerShell CopyFromScreen）→ 存 `pending/<实例>/…png`；
2. `screenReadEnabled` → 读前台窗口标题；
3. 消息里带最多 2 张未发送的截图路径 + 标题，我这边用 `read_image` 打开。

如果两个开关任一关掉：读屏退化为只读标题；全关时定时唤醒跳过（`no-context-permission`），按钮唤醒发一条无上下文的普通消息。

## 验证步骤

1. 完全退出 DSH → 重启（宿主与主进程代码都改了）。
2. `GET /live2d/health` 应为 `0.13.10`；`GET /live2d/instances` 里各实例的 `wakeCaptureEnabled` 应为 `true`。
3. 点 ⚡：应带截图（唤醒消息里会有「截图：<路径>」）；或看 `/live2d/wake?instanceId=…` 的 `pendingShots`。
4. 设置页动作页点「点头」：应看到连点三次（约 2 秒）。

## 已知限制

- 触发截图时若前台是受保护内容（部分游戏全屏独占），CopyFromScreen 可能拿到黑图；此时仍会附标题。
- 动作仍是 3 秒冷却；一次只播一个动作。
- 迁移只跑一次：`config.json` 里 `migrated` 已含 `0.13.9-mode-switches` 就不会再动开关。
