# 鼻尖黑块 · 排查记录

> 对象：`<你的模型目录>`（新皮，下称「inst-2」）
> 对照：`<你的模型目录>`（下称「inst-1」，渲染正常）
> 记录时间：2026-11-07

## 1. 现象

- 只有 inst-2 在**鼻子位置**出现一个方块状黑块（约几个像素见方，中间更黑）。
- 位置固定在脸部中央，不随窗口大小/缩放变化（按模型坐标定位）。
- 皮肤其余部分、表情、动作都正常。
- inst-1 无此现象。

## 3. 本轮做过的改动（只改诊断，未改渲染逻辑）

| 文件 | 改动 | 目的 |
| --- | --- | --- |
| `electron/renderer.js` | `detectModelParams()` 末尾上报 `{type:'state', phase:'model-textures'}`，读 **`model.textures`**（原来读 `internalModel.textures`，该版本不存在 → `count` 恒 0），每张报 `{i, valid, failed, w, h}`，另报 `managerCount`、`maxTextureSize` | 判断是「纹理没上传」还是别的 |
| `index.js` | `applyWindowMessage` 新增 `model-textures` 分支 → `state.renderer.textures`；`instanceSummary` 暴露 `renderer.textures` | 让 `/live2d/instances` 能读到 |
| `.tmp/runtime-probe/probe.html` | 加 `?premul=1` → `textureOptions.premultipliedAlpha = true` | 二分 premultipliedAlpha |

> 曾走过的弯路：第一版诊断读 `internalModel.textures`，该属性在 pld 0.4 里不存在，`count` 恒 0，等于空跑一轮。

## 5. 已排除

| 假设 | 证据 | 结论 |
| --- | --- | --- |
| 纹理上传失败 | 5/5 `valid=true failed=false`，尺寸均正确 | ❌ 排除 |
| 显存/纹理尺寸超限 | 最大 8192×8192，`MAX_TEXTURE_SIZE=16384` | ❌ 排除 |
| premultipliedAlpha 设置错 | 探针加 `?premul=1` 重渲染，两版脸图逐像素一致 | ❌ 排除 |
| moc3 版本不兼容 | 两个模型都是 `MOC3` version 5，inst-1 正常 | ❌ 排除 |
| 我的窗口/交互逻辑引入 | 在**干净探针页面**（只有 pixi + pld + core）渲染同一模型，黑块同样出现 | ❌ 排除（问题在渲染库×模型，不在插件） |

> 用户补充：该皮是公皮，其他人用/做插件无此反馈 → 进一步说明不是「模型文件损坏」，更可能是**某个特性的支持差异**。

## 6. 剩余可能原因（按可能性排序）

### ① `MultiplyColor / ScreenColor`（Cubism 4.2+）不被 pld 0.4 支持 ★最可疑
- Cubism 4.2 起每个 drawable 可带 multiply / screen 颜色。
- `pixi-live2d-display` 0.4.0 发布于 Cubism 4.2 之前，**没有实现这两组属性**。
- 若该皮在导出时给某个部件设了「正片叠底 = 黑」，0.4 会忽略 → 通常表现为「没效果」，但也可能因为内部走 `_model` 的 multiply buffer 默认值（全黑）而算成黑色。
- 位置在鼻尖、形状是方块 —— 与「一个独立的小 drawable（高光/阴影）被乘成黑」高度吻合。

### ② Masking / 剪裁区处理异常
- 若该 drawable 被某个 mask 剪裁，而 0.4 的 clip 实现处理 4.2 的 clip 数据不完整，可能出现「裁剪区被涂黑」的方块。
- 线索：黑块边缘很直、尺寸像矩形，符合 mask 区域。

### ③ 该 drawable 的纹理 UV 落在全黑/透明像素
- 素材或导出问题：某个小部件引用了纹理上一块纯黑区域。
- 但公皮无人反馈，可能性较低。

### ④ 参数默认值把某个颜色/透明度参数按到 0
- 某些皮用参数驱动 drawable 的 opacity / 颜色。若某参数默认 0 而我们没在 cdi3 里读到它，可能显示为黑。
- 线索：可通过 `/live2d/params` 对照该皮参数表排查。

### ⑤ 多纹理绑定槽位错乱
- 5 张纹理，若 drawable 的 textureIndex 与绑定槽不一致，会取到别的纹理（可能黑）。
- 但 `textures` 5 张都 valid，槽位错乱通常会是大面积错乱，不像单点黑。

## 7. 建议的验证顺序（成本从低到高）

1. **他人对照**（最省事）：让作者或其他人用 Cubism Viewer / VTube Studio 打开同一皮，看鼻尖是否也有黑块 → 有=素材问题；无=渲染差异，继续 2。
2. **读 multiply colors**：用 Cubism Core 的 `csmGetDrawableMultiplyColors`（或读 moc3 的 drawable 段）检查是否存在非白色 multiply → 若存在，基本可定性为 ①。
3. **换 pld 0.5.0-beta**：在探针里临时换 `cubism4.min.js` 的 beta 版本（不改插件），看黑块是否消失 → 消失=①被修了。
4. **二分隐藏 drawable**：在探针里按索引把 drawable 的 opacity 依次置 0，定位是哪个 drawable 后看它的纹理/颜色属性。

## 8. 当前处置

- 用户的决定：**先放着，自己对比后再定**。
- 代码侧不做任何渲染改动（避免瞎改引入新问题）；诊断能力保留（`renderer.textures` 可随时查）。
- 若后续确认是 ①/②，修法分别是：升级/替换渲染库（成本高），或在渲染层对特定 drawable 做兜底（可尝试，需先定位）。
