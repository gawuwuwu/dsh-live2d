# 0.12.19 可移植性（换机器 / 上传仓库后别人能跑）

目标：不把「我这台机器」的布局写死。默认值仍然偏向本机体验，但**换机器时不会崩、会给出可执行的提示**。

## 1. 换机器要改的三处

| 位置 | 默认值 | 换机器怎么办 | 不改会怎样 |
| --- | --- | --- | --- |
| 实例「模型路径」 | `<你的模型目录>` | 设置页每张卡片里的「模型」直接填新目录 | 窗口显示占位卡，设置页黄条告警「模型路径不可用」，插件本身仍 ready |
| 全局 `modelRoots` | 空 → 回落 `<模型扫描根>` | 改 `%USERPROFILE%\.dsh\dsh-live2d\config.json` 的 `modelRoots: ["E:\\Live2D"]` | 只是主页「模型」下拉列不出东西；仍可手填路径 |
| 实例「参考音」 | 空（用服务端默认音色） | 设置页「语音」填本机 `.wav` | 填了不存在的文件时，合成返回 `tts-prompt-missing` 并提示去哪改 |

`modelRoots` 规则：最多 5 个，去空去重；非数组按空处理并记 warning。

## 2. 具体改动

### 配置层（`index.js`）

- `DEFAULT_CONFIG.modelRoots = []`（空表示用 `DEFAULT_MODEL_ROOT`）；`modelRoots(state)` 统一在这里回落。
- `normalizeModelRoots(value, warnings)`：去空 → 去重 → 截断到 5 个，超出的记一条 warning。
- `normalizeConfig` 接入；`PERSISTED_KEYS` 加入 `modelRoots`（会写进 `config.json`，卸载不丢）。
- `DEFAULT_CONFIG` / `DEFAULT_INSTANCE` 改为导出，测试可以断言默认值。

### 语音（`synthesizeSpeech`）

- 前置检查：`prompt` 为空直接跳过（用服务端默认音色）；非空时用 `existsSync` 判文件。
- 不存在 → `{ ok:false, status:400, code:'tts-prompt-missing', error:'参考音文件不存在：<path>', hint:'去设置页「语音」改成这台机器上的 .wav，或留空用服务端默认音色。' }`。
- `DEFAULT_INSTANCE.ttsPrompt` 由写死的 `<你的参考音>.wav` 改为 `''`。

### 文案

- `index.js` 的 TTS 未启动提示不再点名 `<CosyVoice2 目录>…`，改成「默认端口 7890；启动脚本按你本机安装位置执行」。
- `client.js` 的模型下拉提示改成「扫自配置的模型扫描根（默认 <模型扫描根>，最多 3 层）」。

### 设置页

- 「宿主状态」卡片新增一行「模型扫描根」：显示 `/live2d/models` 返回的 `roots`，为空显示默认值。

## 3. 卸载（为什么 GUI 里会卡）

`dsh plugin --profile desktop remove` 的顺序是：

1. 从 `dsh.profile.bundles` 摘掉插件（很快）；
2. 跑 pnpm 改 `package.json` / `node_modules`。

第 2 步在本机慢，原因不是插件：`pnpm-lock.yaml` 里缺 `dsh-live2d` 的 link importer 条目，pnpm 判定 lockfile broken 后**重新解析 525 个包并联网下载**（日志：`Request took 11902ms`、`Tarball download average speed 6 KiB/s`），看起来像卡死，还会留下「bundle 已摘、dependency 与软链还在」的半卸载状态。

- 对 link 安装的插件，根本不需要 pnpm。用无网络脚本：
  - 卸载：`tools\uninstall-drill.cmd`（或 `node tools/uninstall-drill.mjs --manual-remove --yes`）
  - 安装：`node tools/uninstall-drill.mjs --manual-install` / `--restore`
  - 前后体检：`--check` / `--before` / `--after` / `--verify-installed`
- 脚本只做四件事：改 `package.json` 的 bundles/dependencies、写 `pnpm-lock.yaml` 的 link importer、建/删 junction、逐项校验；每步备份到 `.uninstall-backups/<ISO>/`。
- `.cmd` 是纯 ASCII（避免代码页乱码），不受 PowerShell 执行策略限制（默认 Restricted 跑不了 `.ps1`）。

## 4. 验证

- 单测新增 5 条：`tts-prompt-missing`、参考音默认为空、`modelRoots` 去空去重、最多 5 个。
- `node tools/uninstall-drill.mjs --verify-installed`：bundle / dependency / lock importer / junction / patch 五项全有。
- 真机：删掉模型目录 → 窗口占位 + 设置页告警、插件 ready；改回 → 恢复正常。

## 5. 已知限制

- 扫描根只扫 3 层，模型目录要放在 3 层以内。
- 设置页没有编辑 `modelRoots` 的输入框，只能改 `config.json`（避免误改全局配置；一般场景直接填单实例模型路径就够）。
- 参考音只做存在性检查，不校验格式（服务端会报错）。
