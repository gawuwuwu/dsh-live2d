# 0.13.11 · 模式设置收拢 + 切模式误报修复

## 1. 你反馈的两个问题

### ① 切到「AI 半自动 / AI 自动」时提示「没开定时唤醒」，但实际开着

两个原因叠在一起：

- 提示用的 `owner.config` 是 `patchInstance` 之前的引用，切模式后配置对象已重建，读到的是旧值 → 现在改用 `findInstance(...)` 重新取一次。
- 「一键开启模式所需开关」原来只开了三个（读屏标题 / 允许截图 / AI 移动窗口），**没包含 `wakeEnabled`**，所以点过一键开启的人仍然没有定时唤醒。现在把 `wakeEnabled` 也纳入。

### ② 模式相关的开关散在「模型」页和「模式设置」页，两处都有

- 模型页删掉：主动唤醒（开关 + 间隔 + 额度 + 唤醒截图）、AI 移动窗口、读屏标题、定时感知、定时间隔、允许截图、截图免确认、截图间隔、点模型反应、空闲小动作。
- 模型页现在只留模型/显示相关：模型路径、尺寸位置、缩放、布局、渲染/穿透/自动开窗/调整大小、思考超时、语音、测试与维护。
- 模型页原来的「主动感知」位置改成一行提示，指向「模式设置」。

## 2. 模式设置页现在的结构

顶部：调整哪个模型下拉、当前模式、一键开启、黄字提示（任一关键开关关闭时）。

**手动**（不主动，只有 ⚡ / 摸模型才回应）

| 项 | 控件 |
| --- | --- |
| 读屏 · 前台标题 | 开关 + 定时感知读取间隔（秒，15~300） |
| 定时感知 | 开关（旧版定时读标题；开定时唤醒后被接管，保持关即可） |
| 允许截图 | 开关 + 最短间隔（秒，5~300） |
| 截图免确认 | 开关（总开关关闭时不生效） |
| 点模型有反应 | 开关 |
| 空闲小动作 | 开关 |

**AI 半自动**

| 项 | 控件 |
| --- | --- |
| 定时唤醒 | 开关 + 间隔（秒，15~600）+ 每小时额度（次，1~360，滚动 60 分钟） |
| 唤醒时截图 | 开关（关 = 只读窗口标题） |

**AI 自动**

| 项 | 控件 |
| --- | --- |
| 交给 AI 移动窗口 | 开关（仅此模式 + 本开关同时满足才允许 move/resize/scale/reset） |

参数输入是**失焦提交**（`onBlur` → PATCH），不会边打字边发请求；保存后自动 `load()` 刷新。

## 3. 一次性迁移（再跑一次）

- `MODE_SWITCH_KEYS` 增加 `wakeEnabled`，共五个：`screenReadEnabled / screenCaptureEnabled / wakeCaptureEnabled / wakeEnabled / aiMoveEnabled`。
- 迁移标记换成 `0.13.11-mode-switches`：重启后会把存量实例这五项里凡是「不是 true」的都打开一次并落盘，然后记标记；之后你手动关掉的不会再被打开。
- 迁移判定从 `inst[key] === false` 改为 `inst[key] !== true`（字段缺失也算没开）。

## 5. 验证步骤

1. 完全退出 DSH → 重启（宿主改了默认/迁移与提示逻辑）。
2. 设置页刷新 →「模式设置」应看到三个分组，每组里都有开关 + 数字输入。
3. 看 `GET /live2d/config`：实例的 `wakeEnabled` 应为 `true`（迁移生效）。
4. 窗口工具栏切到「AI 半自动」：气泡应只说明能力，不再报「定时唤醒未开启」。
5. 「模型1 / 模型2」页：应看不到读屏/截图/唤醒/移动窗口这些开关了。

## 6. 已知限制

- 「定时感知」是旧功能，保留开关但建议保持关闭（定时唤醒已接管）；两者同时开会重复读标题，代码里已让定时唤醒优先。
- 迁移只跑一次；想回到关闭状态，去「模式设置」逐项关。
