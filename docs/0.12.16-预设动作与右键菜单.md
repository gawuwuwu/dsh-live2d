# 0.12.16 预设动作管理（右键菜单 + 自定义动作 + 循环）

用户需求（原话）：

> 预设动作需要能够手动添加/手动调控（如可选择让模型进行惊讶-开心-点头循环，可控制间隔时间），手动添加可让模型自主设计动作加入循环（不需要交互的动作），仅首次添加动作后需要模型设计，之后循环直接通过设计的动作走即可（三种模式均可调用预设动作）。右键模型可点开预设动作框，点击预设动作选项后可让模型立刻进行预设动作。

> 进化我可能放入其他模型，设计代码时不要局限于这一个模型可用，尽量设计为通用。

## 1. 通用性：动作不绑模型

自定义动作描述的是「参数 → 关键帧」，参数可以写：

- **逻辑名**（跨模型通用）：`headX` `headY` `headZ` `eyeOpenL` `eyeOpenR` `eyeBallX` `eyeBallY` `mouthOpen` `mouthForm` `bodyX`
- **真实参数名**（Cubism 原样）：如 `ParamAngleZ`、`PARAM_EXP4`

渲染层（`electron/renderer.js`）：

- `detectModelParams()` 读 `core._parameterIds`（拿不到就用 `getParameterCount()/getParameterId(i)`），把参数表 `report({type:'state', phase:'model-params'})` 报给宿主，存进 `inst.renderer.params`。
- `resolveParam(name)`：先按真实名找，再按 `PARAM_ALIASES` 的候选列表找；都找不到返回 `null`。
- `compileCustomAction(def)`：把每条轨道的参数解析成真实 id，**解析不到的轨道直接跳过**——换模型缺参数不会报错，也不会让整个动作失效。

## 2. 数据结构

```jsonc
// 实例配置
{
  "customActions": [
    {
      "id": "wave",              // ^[a-z][a-z0-9_-]{1,23}$，不能与内置重名
      "label": "挥手",            // ≤24 字
      "durationMs": 1200,        // 200~10000
      "tracks": [
        { "param": "headZ", "keys": [[0, 0], [0.5, 12], [1, 0]] }
      ]
    }
  ],
  "presetSequences": [
    { "id": "user-loop", "label": "设置页循环", "steps": ["happy", "nod"], "intervalMs": 2500, "loop": true }
  ]
}
```

校验（`normalizeCustomActions` / `normalizePresetSequences`）：

| 约束 | 值 |
| --- | --- |
| id | `^[a-z][a-z0-9_-]{1,23}$`，不得与内置动作重名 |
| 轨道数 | ≤8 |
| 每轨关键帧 | ≤12，`t∈[0,1]` 自动排序，`v∈[-40,40]` |
| 时长 | 200~10000ms |
| 循环步骤 | ≤20 个动作 id |
| 循环间隔 | 300~60000ms |

非法项跳过并记 warning，不影响其它动作。

## 3. 右键菜单

- `electron/index.html` 新增 `#preset-menu`（深色浮层，z-index 60）。
- 右键（`contextmenu`）在模型上打开：上半部分是动作（内置 + 自定义），下半部分是循环（每条显示步数，运行中显示「停止」）。
- 菜单打开期间强制 `setIgnoreMouse(false)`（穿透关掉），点外部或 Esc 关闭。
- 点击动作 → `report({type:'preset-play', action})`；点击循环 → `report({type:'preset-sequence', id})`。
- 宿主 `playPreset()` 立刻播（不占 anim 冷却、不走模式守卫——这是用户在自己窗口里点）；`preset-sequence` 在「正在跑就停 / 没跑就开」之间切换。

## 4. 工具（AI 用法）

| 工具 | 用途 |
| --- | --- |
| `live2d_params` | 看当前模型真实参数名（设计动作前先查） |
| `live2d_preset` | `op: list / play / define / remove / sequence / start / stop` |

AI 设计一个动作的典型流程：

1. `live2d_params` 看模型有哪些参数；
2. `live2d_preset { op:"define", action:"wave", label:"挥手", durationMs:1200, tracks:[{param:"headZ", keys:[[0,0],[0.5,12],[1,0]]}] }`；
3. `live2d_preset { op:"sequence", sequenceId:"greet", steps:["wave","happy"], intervalMs:2000 }`；
4. `live2d_preset { op:"start", sequenceId:"greet" }`。

动作定义存进实例配置（`customActions`），**只设计一次**，之后循环直接用 id 跑，不再需要模型参与。

## 5. 设置页

实例卡片新增「循环动作」区块：勾选要进循环的动作（按勾选顺序执行）+ 每步间隔（秒）+「开始循环 / 停止」。保存后写入 `presetSequences` 里 id 为 `user-loop` 的那条。

## 6. HTTP

- `GET /live2d/preset` → `{ presets: {actions, sequences}, running }`
- `POST /live2d/preset` → `{ op: "play"|"start"|"stop"|"list", instanceId?, action?, sequenceId? }`

## 7. 验证

- 单测新增 11 条：合法/非法动作定义、内置重名、空轨道、循环步骤为空、`buildPresets` 合并、`playPreset` 自定义动作与未知动作、序列启动/停止/未知序列。
- 三套测试全过：`shell.mjs`、`client.mjs` 10 项、`renderer-smoke.mjs` 7/7。

手工验收（需重启 DSH + 关窗重开）：

1. 右键模型 → 出现菜单，点任一动作 → 立刻播；
2. 设置页勾两个动作 + 设间隔 2 秒 → 保存 → 「开始循环」→ 按间隔轮流播；
3. 「停止」→ 不再继续；
4. 让 AI 用 `live2d_preset define` 加一个自定义动作 → 右键菜单里能看到并播放；
5. 换一个模型（参数名不同）→ 自定义动作里缺的轨道自动跳过，不报错。

## 8. 已知限制

- 自定义动作是参数关键帧，没有骨骼/Motion 混合；同一时刻只有一个动作在跑。
- 循环是宿主侧的 `setTimeout` 链，插件禁用/卸载即停；`loop:false` 跑完一轮自动停。
- 菜单目前只有「播放/启停」，不支持在菜单里直接编辑动作（编辑走设置页或工具）。
