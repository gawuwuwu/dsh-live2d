# 0.13.0 模式与主动唤醒：审查修订版

日期：2026-11-04  
状态：**设计审定稿，代码未修改**  
关联文档：`0.13.0-模式与唤醒方案.md`

本文件在原始方案基础上吸收代码审查结论，作为后续实施依据。

---

## 1. 最终产品语义

代码中的模式仍保持：

```text
auto   = 自动
semi   = AI 半自动
manual = AI 手动
```

### 1.1 自动

- 不因 DSH 其他会话产生回复而主动弹气泡。
- 不定时唤醒 AI。
- 始终允许空闲动作、循环预设动作、模型点击/摸头反应。
- 用户点击 ⚡ 时，允许进行一次用户授权的唤醒：
  - 优先截图；无截图权限时读前台标题；
  - 两者都不可用时，可发一次无屏幕上下文的普通唤醒，或由策略跳过；
  - 这一次唤醒产生的回复必须允许显示气泡；
  - 不开放 AI 移动窗口。
- 用户在模型输入框主动发送消息时，仍按正常对话处理，不受“auto 不主动唤醒”限制。

### 1.2 AI 半自动

- 保留自动模式的空闲动作和点击/摸头反应。
- 支持用户按钮唤醒和定时唤醒。
- 唤醒回复可以根据前台标题/截图调用表情、动作和气泡工具。
- 不允许移动或缩放整个模型窗口。

### 1.3 AI 手动

- 包含 AI 半自动的全部能力。
- 额外允许 AI 移动、缩放窗口。
- 移动能力受独立开关、工作区边界和恢复机制约束。

## 2. 最终权限矩阵

| 能力 | 自动 | AI 半自动 | AI 手动 |
| --- | --- | --- | --- |
| 空闲动作 / 循环预设 | 允许 | 允许 | 允许 |
| 用户点击/摸头动作 | 允许 | 允许 | 允许 |
| 用户输入框发消息 | 允许 | 允许 | 允许 |
| 用户点击 ⚡ 唤醒 | 允许，一次性 | 允许 | 允许 |
| 定时唤醒 | 禁止 | 允许 | 允许 |
| 唤醒回复气泡 | 允许 | 允许 | 允许 |
| AI 动作 / 表情 | 仅按钮唤醒回合临时允许 | 允许 | 允许 |
| AI 主动气泡 | 仅按钮唤醒回合临时允许 | 允许 | 允许 |
| 前台标题读取 | 仅用户唤醒上下文 | 允许 | 允许 |
| 定时截图 | 禁止 | 允许，需显式授权 | 允许，需显式授权 |
| AI 移动/缩放窗口 | 禁止 | 禁止 | 允许，需 `aiMoveEnabled` |

### 2.1 权限必须包含触发来源

权限判断至少需要：

```text
mode + capability + triggerSource
```

建议来源：

```text
window-chat    用户从模型输入框发消息
external-chat  DSH 主界面正常聊天
wake-button    用户点击 ⚡
wake-timer     插件定时唤醒
preset-tap     用户点击/摸头
ai-tool        AI 回复回合中的工具调用
```

不能再只使用当前 `mode !== 'auto'` 的判断，否则无法表达：

- auto 禁止定时唤醒，但允许按钮唤醒；
- auto 禁止自主动作，但允许摸头预设；
- manual 比 semi 多一项窗口控制。

## 3. 唤醒由宿主负责，不由 AI 自己触发

唤醒链路固定在插件宿主：

```text
按钮 / 调度器
  → 解析实例与绑定会话
  → 检查模式与用户授权
  → 检查 agent 是否忙碌
  → 截图或读取标题
  → 组装唤醒消息
  → agent.followup(message)
  → 等待本轮结束
  → 读取本轮新 assistant 回复
  → 推送到对应实例气泡
```

### 3.1 不新增 AI 自唤醒工具

不提供可创建新一轮对话的 `live2d_wake` 工具。

原因：

```text
AI 回复
→ AI 调用 wake
→ 注入新的 user 消息
→ AI 再次回复
→ 再次调用 wake
```

会形成无限自我唤醒、上下文快速膨胀和额度耗尽。

AI 的职责是：

- 阅读本轮唤醒消息；
- 必要时用 `read_image` 查看截图；
- 调用 `live2d_anim` / `live2d_preset` 控制表情动作；
- 调用 `live2d_bubble` 输出气泡；
- manual 模式可按权限移动窗口。

如需诊断唤醒状态，只在 `live2d_status` 中增加只读信息，不提供创建新 turn 的工具。

## 4. 唤醒状态机

每个实例维护独立唤醒状态：

```text
idle
preparing
capturing
injecting
waiting-agent
waiting-reply
completed
failed
```

### 4.1 忙检查

以下任一情况视为忙：

- 对应 agent 状态为 `running`；
- 实例现有 `chat.pending`；
- 已有一个 wake 正在 `injecting` / `waiting-agent` / `waiting-reply`；
- 同一绑定会话有另一个实例处于唤醒中。

忙时：

- 如果允许截图，本次仍可截图并放入 `pendingShots`；
- 不注入 wake 消息；
- 按钮立即显示“正在回答，稍后”；
- 定时器记录 `skipped:'busy'`。

### 4.2 唤醒回复必须严格绑定本轮

不能简单在 idle 时读取“最后一条 assistant”，否则可能错拿上一轮回复。

唤醒前记录：

```text
baselineAssistantId / baselineHash / sessionSeq
```

唤醒完成后必须同时满足：

- agent 回到 idle；
- 会话里出现新的 assistant 消息；
- 新消息身份与 baseline 不同；
- 未超过本次唤醒的回复超时。

超时后：

- 清理本次 wake 状态；
- 不把其他对话回复误显示到模型；
- 在台账与 UI 给出失败原因。

### 4.3 模式切换

- 切到 auto 时立即停止后续定时唤醒。
- 当前已注入的一轮允许结束，避免留下半截对话。
- 新的一轮不再允许 AI 动作和窗口控制。
- 当前 wake 的权限在触发时做快照，不因中途切换而在同一轮内反复变化。

## 5. 统一调度器

用唯一 wake scheduler 管理 semi/manual 的定时唤醒。

建议 tick：5 秒。

每次 tick 现场检查：

- 实例处于 semi/manual；
- `wakeEnabled=true`；
- 会话仍绑定且 agent 可用；
- 到达 `wakeIntervalMs`；
- 未超过每小时额度；
- 当前实例没有进行中的 wake；
- 当前 agent 不忙。

### 5.1 与现有 screenWatch 的关系

避免同时运行两套主动感知循环。

建议：

- `wakeEnabled` 的实例由 wake scheduler 负责标题/截图与唤醒；
- 旧 `screenWatch` 保留为兼容配置，但不再与 wake 同时重复读取；
- 或在迁移后把 `screenWatchEnabled` 标为废弃兼容字段；
- UI 不得让用户误以为两个“30 秒定时器”都会独立执行。

### 5.2 成本保护

建议默认值：

| 参数 | 默认 | 说明 |
| --- | ---: | --- |
| `wakeIntervalMs` | 60000 | 可调至 30000，但不建议默认 30 秒 |
| `wakeMaxPerHour` | 30 | 滑动一小时窗口 |
| `wakeCaptureEnabled` | false | 定时截图默认关闭 |
| `wakePendingShots` | 2 | 忙时保留截图数 |
| `aiMoveEnabled` | false | manual 模式中还要显式开启 |

达到每小时上限后：

- 暂停定时唤醒；
- 按钮唤醒是否受限需单独定义，建议按钮仍可用；
- UI 显示额度耗尽原因和恢复时间；
- 不静默跳过。

## 6. 截图与标题策略

### 6.1 按钮唤醒

用户点击 ⚡ 可视为这一次截图的明确授权：

- `screenCaptureEnabled=true` 时，传 `confirmed:true` 截一次；
- 截图关闭或被限速时，尝试前台标题；
- 标题读取也关闭时，可发送无屏幕上下文按钮唤醒；
- 用户必须能在按钮反馈中知道本次用的是“截图 / 标题 / 无上下文”。

### 6.2 定时唤醒

定时截图不是用户手势，必须依赖显式预授权：

```text
screenCaptureEnabled
+ wakeCaptureEnabled
+ 用户已了解定时截图提示
```

建议 `wakeCaptureEnabled` 本身就代表“允许定时唤醒截图”，并在设置页明确说明：

> 开启后，定时唤醒会周期性读取整个屏幕；截图保存在系统临时目录，仅保留有限数量。

若截图被 `screenCaptureIntervalMs` 限速：

- 本次降级为标题；
- 标题不可用时跳过本次定时唤醒；
- 不使用空上下文反复唤醒 AI。

### 6.3 截图文件生命周期

- 截图保存到独立临时目录；
- `pendingShots` 使用专用子目录或 pin 标记；
- 待看文件在消费前不能被通用 10 张清理逻辑删除；
- 唤醒投递成功后删除已消费文件；
- 实例删除、wake 关闭、插件卸载时清理；
- 队列溢出时删除最旧且未被其他队列引用的文件。

### 6.4 图片交付

唤醒消息写入绝对路径，并明确提示：

```text
截图 A：%USERPROFILE%\AppData\Local\Temp\dsh-live2d-screens\pending\shot-xxx.png
截图 B：...
请先使用 read_image 查看，再决定动作和回复。
```

若运行环境不能保证 `read_image` 可用：

- 不承诺 AI 真能看图；
- 至少使用标题生成回复；
- 在工具/健康状态中报告图片读取依赖不可用。

## 7. 会话与回复回流

### 7.1 使用当前绑定会话

唤醒通过绑定会话的 `agent.followup()` 注入一条 user 消息。

建议消息：

```text
[Live2D 主动唤醒]
时间：HH:mm
来源：button / timer
模式：semi / manual
前台：窗口标题（进程名）
截图：临时文件绝对路径
待看旧截图：最多 2 张

请用一两句话回应用户当前正在做的事。
可以调用 live2d_anim / live2d_preset 表达情绪，不要长篇。
```

消息带：

```text
source.kind = "live2d-wake"
source.trigger = "button" | "timer"
source.instanceId
```

### 7.2 会话污染的边界

采用主会话意味着：

- 注入消息和 AI 回复会进入主对话历史；
- `source.kind` 只能帮助 DSH/插件标记与过滤；
- 不能保证从 DSH 核心上下文中完全隐藏。

如果要求绝对不进入主历史，只能使用隐藏会话，但会失去当前对话上下文，不建议默认采用。

### 7.3 气泡回流

回复完成后：

- 唤醒产生的回复允许显示气泡，即使当前是 auto；
- 普通 auto 空闲回复仍不显示；
- 用户输入框和 DSH 主界面的正常回复继续显示；
- 气泡身份必须来自本次 wake 的新 assistant 消息；
- TTS/口型在 wake 回复成功后复用现有语音链路。

## 8. 工具栏与设置页

### 8.1 工具栏

建议顺序：

```text
[✥] [模式 ▾] [⚡] [📌] [×]
```

- 模式菜单显示三项：自动 / AI 半自动 / AI 手动。
- 菜单由宿主配置决定当前值，不使用 renderer 独立循环状态。
- ⚡ 处理中显示 `…`；完成后短暂显示：
  - `✓ 已完成`
  - `忙`
  - `未绑定`
  - `无权限`
- 240px 窄窗口下，会话标题的可用宽度需同步缩短，避免与工具栏重叠。
- 菜单、按钮仍保持 `no-drag` 和高于调整框的 z-index。

### 8.2 设置页

新增实例级设置：

- 定时唤醒开关；
- 唤醒间隔；
- 定时截图授权；
- pending 截图上限；
- 唤醒后自动朗读；
- 每小时上限；
- manual 模式 AI 窗口移动开关；
- 最近唤醒台账与跳过原因。

## 9. 工具接口调整

### 9.1 不新增 `live2d_wake`

唤醒只由宿主按钮或调度器发起。

`live2d_status` 可以增加：

```text
wake.phase
wake.lastAt
wake.lastSource
wake.lastSkipReason
wake.pendingCount
```

### 9.2 保留 `live2d_window` 的 action 字段

现有工具使用 `action`，不要直接改名为 `op` 造成兼容破坏。

扩展为：

```text
action:
  open
  close
  reload
  move
  resize
  scale
```

其中：

- `move/resize/scale` 只在 manual；
- `autoMoveEnabled=true`；
- 参数经过宿主边界校验；
- 返回最终 bounds；
- 不能绕过窗口最小尺寸和工作区限制。

### 9.3 动作控制

- semi/manual 的正常 AI 回合允许 `live2d_anim` / `live2d_preset`；
- auto 仅在 `wake-button` 授权回合临时允许；
- 用户点击/摸头始终可走预设动作，不受 AI 工具模式闸限制。

## 10. manual 移动与遮挡安全

“挡住屏幕”属于高风险桌面控制能力，需要硬边界：

- 默认 `autoMoveEnabled=false`；
- 只有 manual 且用户显式开启；
- 窗口不得移出所有屏幕工作区；
- 至少保留一块可见的工具栏和恢复入口；
- 单次移动距离与频率限速；
- 尺寸仍受现有 160×200 至 800×1000 约束；
- 提供“恢复默认位置/大小”；
- AI 不得连续高频移动阻止用户操作；
- 窗口穿透状态不得因移动自动改变。

如果产品只需要“模型在窗口内移动/放大”，应提供模型级 transform，不要直接控制整个桌面窗口；两种能力应分开命名。

## 11. 风险审查

### 11.1 成本

30 秒定时唤醒成本过高：

- 每小时最多 120 个 user turn；
- 每轮都可能附带截图；
- 图像 token、模型 token 和 TTS 成本叠加；
- 主会话历史迅速增长。

因此推荐 60 秒默认、截图默认关闭、每小时 30 次上限。

### 11.2 隐私

- 定时截图默认关闭；
- 开启时必须有明确说明；
- 截图只存临时目录；
- 待看截图及时清理；
- 按钮唤醒与定时授权分开；
- auto 定时唤醒完全禁止。

### 11.3 自我循环

- AI 不拥有 wake 注入工具；
- wake 消息来源固定为宿主；
- 同实例单飞；
- 同会话串行；
- 超时或失败后解除状态；
- 每小时额度硬限制。

### 11.4 错配回复

- 唤醒前建立 baseline；
- 只接受本轮新 assistant；
- 不同 session/instance 不得混用；
- 超时不推上一轮最后回复。

## 12. 测试计划

### 12.1 权限矩阵

- auto 定时唤醒禁止；
- auto 按钮唤醒允许；
- auto 摸头预设允许；
- semi/manual 定时唤醒允许；
- manual 移动允许；
- semi 移动拒绝；
- 模式热切换立即生效。

### 12.2 调度与成本

- 到达间隔才唤醒；
- 间隔热更新；
- 忙时不注入；
- 每小时上限；
- auto 不计入按小时上限；
- 关闭 wake 后不再触发。

### 12.3 忙与 pendingShots

- 忙时截图成功入队；
- 队列上限 2，丢最旧；
- 下次唤醒带 2 张；
- 成功后清空已消费截图；
- 文件被 pin 后不会被通用 pruner 删除；
- 实例删除时清理。

### 12.4 回复关联

- 新 assistant 回复显示气泡；
- 上一轮 assistant 不误推；
- 超时清理；
- followup rejection 被捕获；
- agent idle 事件丢失时有超时兜底。

### 12.5 截图与标题

- 按钮截图；
- 截图关闭回退标题；
- 截图限速回退标题/跳过；
- 定时截图未授权不截；
- 标题与截图都关闭的行为符合策略。

### 12.6 UI

- 模式菜单与设置页一致；
- 模式切换持久化；
- 窄窗口按钮不重叠；
- wake 按钮忙碌/完成/错误反馈；
- 手动模式下提供恢复位置入口。

## 13. 验收标准

1. auto 不再定时唤醒，也不因其他 DSH 对话的空闲回复主动弹气泡。
2. auto 保留空闲动作和摸头反应。
3. 三个模式都能通过按钮主动唤醒一次。
4. semi/manual 按配置定时唤醒。
5. auto 按钮唤醒的回复允许显示气泡。
6. semi/manual 的 AI 可以根据截图/标题调用动作、表情和气泡。
7. 忙时截图保留，最多两张在下次唤醒带入。
8. AI 无自唤醒工具，不会形成递归对话。
9. manual 才能移动/缩放窗口，并且始终可恢复。
10. 所有截图和唤醒动作均可在 diag/health 中审计。

1. 模式权限矩阵与回复来源标记。
2. wake 状态机、回复 baseline 和超时。

4. 截图授权、临时文件和 pending 队列。

7. manual 窗口移动/缩放及安全恢复。
8. 单元测试、调度探针、渲染冒烟和真机验收。
