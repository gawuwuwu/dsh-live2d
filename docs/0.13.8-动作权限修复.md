# 0.13.8 · 「设置页点动作没反应」修复

## 现象

设置页动作页里，无论点哪个默认动作、或者启用动作循环，模型都不动。

## 根因

动作权限只按「模式」判，没区分「谁发起的」：

```js
// 旧：handleAnim
const guard = body.auto === true || modeAllows(state, 'anim') ? null : modeForbidden(state, 'anim')
```

- `modeAllows` 在 `mode === 'auto'`（界面显示「手动」）时恒 false；
- 设置页的「试玩」按钮走 `POST /live2d/anim` → `handleAnim(...)` → 被 403 `mode-forbidden`；
- 而两个实例当前都是 `auto`，所以**每一次点击都被拒**。

循环本身不经过这个守卫（`playPreset` / `startPresetSequence` 直接下发 `{type:'anim'}`），但用户点「启用」时若还没保存过循环，`presetSequences` 为空 → `no-such-sequence`，也没有明确提示，看起来同样「没反应」。

## 修法

1. 权限改成按来源（`canControl` 的第四维）：
   - `CONTROL_SOURCES` 新增 `'ui'`；
   - `canControl(inst, 'anim', { source: 'ui' })` 直接放行（用户亲手点的不算 AI 控制）；
   - `handleAnim(state, log, body, source = 'ui')`——HTTP 路由保持默认 `'ui'`，AI 工具显式传 `'tool'`，`auto:true` 的内部动作照旧放行。
2. 循环补校验：`startPresetSequence` 对空 steps 返回 `{ code:'empty-sequence', error:'循环「X」没有动作步骤，先勾选动作再保存' }`。
3. 测试同步：原「自动模式拒绝动作指令」拆成两条——`source:'tool'` 仍 403、`source:'ui'` 可播。

## 现在各入口的行为

| 入口 | 来源 | auto（界面「手动」）行不行 |
| --- | --- | --- |
| 设置页「试玩」按钮 | `ui` | ✅ 能播 |
| 窗口右键菜单 | `preset-tap` / `ui` | ✅ 能播 |
| 设置页循环启用 | 直接下发 | ✅ 能播（需先保存循环） |
| AI 工具 `live2d_anim` | `tool` | ❌ 403（符合「自动模式不让 AI 自己动」） |
| AI 工具 `live2d_preset play` | `tool` 路径无守卫 | ✅（预设动作是用户/AI 设计好的，不算「主动控制」） |
| 半自动自动反应（`auto:true`） | 内部 | ✅ |

## 实机验证步骤

1. 完全退出 DSH → 重启（宿主代码改了）。
2. 设置页 → 动作 → 「默认动作」点 `点头/歪头/开心`：模型应立即动；返回提示「动作已发送：nod」。
3. 新建循环：勾 2~3 个动作、间隔 3 秒 → 「保存循环」→ 列表出现该循环 → 「启用」：应看到按顺序循环播放；「停止循环」应停下。
4. 把模式切到「AI 自动」再点一次动作：**仍然能播**（这是本次修复的重点）；但让 AI 用工具 `live2d_anim` 应被拒。

## 已知限制

- 动作仍有 3 秒冷却（`animCooldownMs`），连点会返回 429「动作冷却中」，这是预期行为。
- 循环的最短间隔 300ms、最长 60s；动作本身时长见各 `ANIMS`。
