# 0.13.6 · codex 遗留五项修复

来源：codex 0.13.5 报告「仍需注意的既有问题」。这轮只修这 5 项，白底链路沿用 0.13.5。

## 1. 窗口对话可能「有气泡但输入框一直思考中」

**原因**：`pushIdleReplies` 先按 messageId 原子领取并显示气泡，400ms 后 `maybeFinishChat` 再领一次时失败，直接 `return`——`state.chat.pending` 已清，但**没有给窗口发任何完成消息**，渲染层 `loadingEl` 永远收不掉。

**修法**：
- 新增 `notifyChatDone(state, requestId)` → 下发 `{ type:'chat-status', phase:'done', requestId }`。
- `maybeFinishChat` 的三条「不弹气泡」出口都改成「清 pending + 通知窗口收尾」：
  1. 本轮没有新回复（`identity` 为空或没变）；
  2. `findLatestAssistantText` 取不到；
  3. claim 失败（气泡已被别的路径显示）。
- `renderer.js` 的 `handleChatStatus` 增加 `phase === 'done'` 分支：`clearLoading()` + `finishChat()`。

## 2. 窗口对话可能在中途 assistant 消息上提前结束

**原因**：`maybeFinishChat` 只看「最后一条 assistant 变了」，没要求 agent 已经 `idle`。工具调用往返期间落盘的那条 assistant 会被当成最终回答。

**修法**：`maybeFinishChat(state, ctx)` 新增 `ctx` 参数（`finishChatsEverywhere` 传 `state.ctx ?? state.root?.ctx`）；轮询回调里先判 `agentIsRunning(ctx, pending.sessionId)`，仍在跑就重新排一次 400ms 延时，不结束。

## 3. 忙时唤醒的截图被丢弃

**原因**：`wakeUp` 忙分支调用 `collectWakeContext` 后丢掉返回值，但截图在 `collectWakeContext` 里已经被打上 `sentAt`，下一轮「只取未发送」时永远取不到 → 违背「下次唤醒带两张截图」。

**修法**：`collectWakeContext(root, inst, log, { markSent = true })`；忙分支传 `{ markSent: false }`——只采集入队，不消费，`shots` 返回空数组（这一轮本来就不发消息）。

## 4. 6 秒时间节流可能吞掉合法回复

**原因**：`AUTO_BUBBLE_THROTTLE_MS` 的检查在 `claimReply` 之前。两轮对话很快结束时，第二轮的 messageId 虽然是新的，也会被时间窗挡掉，且**没有 claim**，之后再也不会显示。

**修法**：删除该时间节流。去重只由 `claimReply`（messageId 维度，文本键 5 秒兜底）承担——同一轮重复事件不会重弹，不同轮次各弹一次。
`AUTO_BUBBLE_THROTTLE_MS` 常量保留导出（兼容外部引用），但不再参与判定。

## 5. 删除实例时 pending 截图未清理

**修法**：`deleteInstance` 里先删该实例 `inst.wake.shots` 里的文件，再 `rmSync(WAKE_PENDING_DIR/<instanceId>, { recursive: true, force: true })`；失败只忽略，不影响删实例。

## 测试

- `node tests/shell.mjs`：全过（原「6 秒内节流」用例改为「去掉时间节流后新消息立即可推」）。
- `node tests/client.mjs`：10 项全过。
- `node tests/renderer-smoke.mjs`：预期 `pass=8`（含 0.13.5 新增的超屏坐标夹取用例），需在真实桌面会话跑。
- `node --check index.js` / `node --check electron/renderer.js` 通过。

## 验收要点（实机）

1. 窗口输入一条消息：气泡出现**同时**输入框的「思考中」消失（不再卡住）。
2. 让 AI 连做两次工具调用：输入框不会在中间那条消息后就结束。
3. 唤醒时若上一轮没结束：这一轮的截图应留在 pending，下次唤醒消息里带两张。
4. 两轮对话很快连续结束：两条回复都应各自出现气泡。
5. 删掉模型 2：`%USERPROFILE%\.dsh\dsh-live2d\pending\<实例id>\` 目录消失。

## 已知限制

- `maybeFinishChat` 依赖 agent 状态；如果 agent 卡在 running 永不回 idle，输入框会一直「思考中」直到 `chatTimeoutMs` 的本地兜底。
- pending 截图仍只在「采集时」做 10 分钟过期清理，长期不开唤醒不会自动删（体积很小，单张 ~5MB，最多 2 张/实例）。
